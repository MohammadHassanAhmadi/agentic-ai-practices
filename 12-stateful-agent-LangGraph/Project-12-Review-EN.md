# Project 12 Review — EN

## Core Idea
Project 12 rebuilt the Stateful Agent from Project 11 using LangGraph.

The main learning goal was to understand how a framework abstracts the manual concepts we already implemented.

## Key Concepts

### StateGraph
Defines the workflow structure.

### AgentState
Shared state passed between nodes.

```python
class AgentState(TypedDict):
    messages: Annotated[list, add_messages]
```

### Node
A unit of work inside the graph.

Examples:
- LLM node
- Tool node
- Approval node

### Edge
Defines where execution goes next.

- `add_edge()` → fixed route
- `add_conditional_edges()` → runtime decision

### messages + add_messages
Conversation history is stored inside state.

`add_messages` merges new messages with existing history instead of replacing them.

### Tool Calling
Tools are bound to the model:

```python
llm_with_tools = llm.bind_tools(tools)
```

`ToolNode` executes tool calls produced by the LLM.

### LLM ↔ Tool Loop

```text
LLM
 ↓
tool needed?
 ↓ yes
ToolNode
 ↓
LLM
```

### thread_id
Identifies one persistent conversation/run.

Equivalent conceptually to `run_id` from Project 11.

### Checkpointer
Stores and restores graph state.

- `InMemorySaver` → temporary
- `SqliteSaver` → persistent

### Persistence
Using the same `thread_id`, LangGraph can restore previous messages/state after restarting the process.

### interrupt()
Pauses execution intentionally.

Resume with:

```python
Command(resume="yes")
```

Typical use cases:
- Human approval
- Human-in-the-loop
- Sensitive action confirmation
- Waiting for external input

## Interview Questions

### What is LangGraph?
A framework for building stateful, graph-based agent workflows with routing, persistence, tools, and resumable execution.

### What is the difference between state and messages?
`messages` represent conversation history. State can contain messages plus any other workflow data.

### Why use a reducer such as add_messages?
To define how updates are merged into existing state instead of overwriting it.

### What is thread_id?
An identifier used by the checkpointer to associate checkpoints with a specific conversation/run.

### InMemorySaver vs SqliteSaver?
In-memory state disappears when the process exits. SQLite persists checkpoints to disk.

### What does ToolNode do?
It executes tool calls generated by the model and returns tool results back into the graph state.

### What is interrupt() used for?
To intentionally pause execution and resume later, commonly for human approval.
